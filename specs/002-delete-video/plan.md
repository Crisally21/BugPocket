# SDD — Технический план удаления видео

**Статус:** черновик, ожидает утверждения `spec.md`.

## 1. Исходное состояние (просмотренная ветка `master`)

- `src/main/java/ru/codex/codextest/model/AttachmentFileType.java`: перечисления MP4/MOV/MKV/AVI/WEBM и MIME-типы.
- `src/main/java/ru/codex/codextest/model/AttachmentMediaKind.java`: IMAGE, VIDEO, DOCUMENT.
- `src/main/java/ru/codex/codextest/service/AttachmentService.java`: зависимость от `VideoPreviewGenerator`, ветка обработки VIDEO, сохранение previewKey, удаление превью.
- `src/main/java/ru/codex/codextest/service/VideoPreviewGenerator.java`, `VideoPreviewProcess.java`, `VideoPreviewWorker.java`: отдельная обработка видео.
- `src/main/java/ru/codex/codextest/controller/AttachmentController.java`: endpoint `/content` выбирает файл превью по previewKey.
- `src/main/java/ru/codex/codextest/model/BugAttachment.java`: `previewKey`.
- `src/main/resources/static/app.js`: `mediaKind === 'VIDEO'`, упоминания видеопревью, два файловых input без `accept`.
- `pom.xml`: `org.bytedeco:javacv-platform`.
- `README.md`, `specs/001-bug-evidence/*`: материалы содержат сценарии с видео.

Это подтверждённые точки по просмотренным файлам. Полный реестр тестов, миграций и иных ссылок необходимо завершить поиском по репозиторию **до изменений**.

## 2. Подход

Работать в **одной ветке** `refactor/remove-video-attachments` (название можно изменить до начала). Базу выбирать после проверки открытого PR `ci/jenkins`, чтобы не потерять CI-изменения и не включить случайно посторонний рефакторинг.

1. Зафиксировать контрольный коммит, проверить чистое рабочее дерево, найти все использования `VIDEO`, `video-preview-worker`, `previewKey`, `javaCV`, `FFmpeg`, расширений видео и тестовых фикстур.
2. Обновить SDD-документы в рабочей ветке — отражать только принятые требования.
3. Убрать VIDEO и видеоформаты из перечислений. Для неизвестных расширений в `AttachmentFileType` сделать детерминированную доменную ошибку «Формат файла не поддерживается» вместо исходного сообщения `valueOf`. Сохранить корректное поведение для отсутствующего имени и пустого файла согласно существующим правилам.
4. Удалить ветку VIDEO и зависимость `VideoPreviewGenerator` из `AttachmentService`. Удалить `previewKey` из `BugAttachment`; упростить `/content` до обслуживания изображения, не ломая отображение PNG/JPG/JPEG.
5. Удалить `VideoPreviewGenerator`, `VideoPreviewProcess`, `VideoPreviewWorker` и **проверить точку входа приложения** на специальный аргумент worker. Убрать `javacv-platform` из `pom.xml` и связанные только с видео ресурсы.
6. В `app.js` удалить VIDEO-ветку отображения, пояснения про видео и задать `accept` для **обоих** полей выбора файлов. Убедиться, что текст ошибки от API виден пользователю; не добавлять отдельные баннеры.
7. Найти исходную миграцию `bug_attachment.preview_key`; добавить **новый** changeSet `dropColumn` (при существовании колонки). Старые миграции не переписывать, учитывая применение Liquibase на существующей базе. Проверить согласованность JPA `ddl-auto=validate`.
8. Удалить только видео-специфичные тесты и фикстуры, при этом общие attachment-тесты адаптировать лишь там, где без этого не компилируются. Добавить минимальную негативную API-проверку неподдерживаемого формата в общий набор тестов, если её не существует: это проверка списка допустимых форматов, а не отдельный набор видеотестов.
9. Обновить `README.md` и SDD, заменить примеры на изображения/документы. Исключить из текста старые инструкции по JavaCV, FFmpeg и обработке видео.
10. Прогнать `mvn -B -ntp clean test`, `mvn -B -ntp package -DskipTests`, `npm ci`, `npm run check:ui`, `npm run test:ui`; проверить миграцию на тестовой БД с прежней схемой и запуск приложения с PostgreSQL. При доступном Jenkins — проверить pipeline в одной PR.

## 3. Риски и меры

- **Схема:** удаление `preview_key` возможно только после подтверждения, что нет нужных данных; заказчик сообщил, что база пуста. Для повторного применения на существующей схеме нужна новая миграция, а не правка истории.
- **Ошибка формата:** исключение из enum без преобразования ошибки может вернуть не тот пользовательский текст. Обработать на сервере.
- **Проверка контента:** расширение и MIME-файл не следует путать; сохраняем все уже существующие механизмы валидации изображений и PDF.
- **Регрессия:** оставляем механизм превью обычных изображений и скачивания оригинала.
- **CI:** проверять, из какой ветки запускается `Jenkinsfile`; отдельный PR `ci/jenkins` ещё может быть не в `master`.

## 4. Готовность к слиянию

Все AC из `spec.md` выполнены; зависимости видео отсутствуют в коде и runtime; миграция проверена; тесты, сборка и UI-проверки успешны; diff не затрагивает сторонние фичи. Подготовить краткое описание PR с результатами проверок.
