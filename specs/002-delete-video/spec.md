# SDD — Удаление поддержки видео из вложений BugPocket

**Статус:** черновик на утверждение заказчиком  
**Feature:** `remove-video-attachments`  
**Ветка (предлагаемая):** `refactor/remove-video-attachments`  
**Область:** только удаление видеофункциональности. Все остальные возможности BugPocket сохраняются.

## 1. Цель

Полностью исключить видео из поддерживаемых вложений BugPocket, сохранив работу изображений и документов, а также остальные сценарии учёта багов.

## 2. Подтверждённые решения заказчика

- Допустимые вложения: **PNG, JPG, JPEG, TXT, LOG, PDF**.
- В стандартном окне выбора файлов следует показывать только разрешённые типы. Это фильтр выбора, а не единственный механизм защиты.
- Для неподдерживаемого формата возвращать текст: **«Формат файла не поддерживается»**. Проверка обязательна на сервере, в том числе для прямых multipart API-запросов.
- Не добавлять отдельное пояснение в интерфейс о том, что поддержка видео удалена. При этом существующие пользовательские тексты и примеры, упоминающие видео, исправить на разрешённые форматы.
- Существующие лимиты загрузки и правила пакетной обработки не менять.
- Полностью убрать `VIDEO` из модели типов вложений и все видеоформаты.
- Удалить видеопревью, связанные классы, JavaCV/FFmpeg и специфические тесты.
- Удалить неиспользуемое поле `preview_key` (Java `previewKey`) из схемы БД через Liquibase, если оно существует.
- README, спецификации, технический план, задачи и API-примеры актуализировать.
- Всё выполнить как одну фичу в одной ветке.
- **По информации заказчика, база пуста:** перенос или сохранение ранее загруженных видео не требуется.

## 3. Функциональные требования

### FR-01. Форматы

Приложение разрешает загрузку изображений PNG/JPG/JPEG и файлов TXT/LOG/PDF. Иные типы отклоняются с сообщением «Формат файла не поддерживается». Нельзя считать `accept` у HTML input серверной валидацией.

### FR-02. Варианты загрузки

Требование FR-01 действует при выборе файлов в UI в форме создания бага, при добавлении к существующему багу и при вызове `POST /api/bugs/{bugId}/attachments` напрямую.

### FR-03. Работа поддерживаемых форматов

- Изображения сохраняются, отображаются как изображения, скачиваются в исходном виде и удаляются.
- TXT, LOG и PDF сохраняются, скачиваются и удаляются; встроенный просмотр содержимого не добавляется.
- Имена файлов, содержимое, поля карточки, URL связанной задачи, статус и приоритет бага остаются без изменений по семантике.

### FR-04. Лимиты и пакетная загрузка

**Не менять текущие действующие правила**, включая максимальный размер одного файла, суммарную квоту бага, частичный успех при ошибках отдельных файлов, атомарный отказ при превышении квоты, и конкурентные операции.

По текущей спецификации ветки `master`: размер одного файла и общая квота — **25 000 000 байт**, **отдельного лимита по количеству нет**. Если актуальная целевая ветка уже отличается, сначала выявить расхождение и согласовать его, не подменяя правила старой версией требований.

### FR-05. UI

В обоих файловых инпутах задать фильтр разрешённых форматов (например, `accept=".png,.jpg,.jpeg,.txt,.log,.pdf"`), убрать отображение видео-превью и связанные пояснения. Не изменять превью изображений.

### FR-06. API и модель

Из списка допустимых `AttachmentFileType` убрать MP4, MOV, MKV, AVI, WEBM; из `AttachmentMediaKind` убрать VIDEO. Протокол для поддерживаемых вложений и имена действующих endpoints сохранить. Модель и DTO должны обслуживать только IMAGE и DOCUMENT.

### FR-07. Хранение

После исключения видеопревью удалить исключительно связанные с ними механизмы и неиспользуемое поле `preview_key` / `previewKey`; не менять ключ хранения оригинального вложения. Изменения схемы — посредством новой миграции Liquibase; ранее применённые changeSet'ы не редактировать.

### FR-08. Документация

Заменить видео-примеры на примеры разрешённых типов и удалить неактуальные требования, инструкции по видеообработке и упоминания JavaCV/FFmpeg. Не добавлять новый пользовательский раздел «Видео запрещено».

## 4. Критерии приёмки

- **AC-01:** PNG/JPG/JPEG успешно загружаются, показываются и скачиваются.
- **AC-02:** TXT/LOG/PDF успешно загружаются и скачиваются с исходными байтами и именем.
- **AC-03:** Окна выбора файлов в двух UI-сценариях фильтруют форматы до разрешённого списка.
- **AC-04:** API отклоняет каждый неподдерживаемый формат с установленным сообщением, даже если запрос отправлен минуя UI.
- **AC-05:** У поддерживаемых вложений без регрессии работают удаление, список и `/content` для изображений.
- **AC-06:** Существующие лимиты и правила пакетной загрузки работают как до изменения.
- **AC-07:** Приложение стартует без JavaCV/FFmpeg и без запуска video-worker; компиляция и тесты проходят.
- **AC-08:** В новой схеме нет `preview_key`; миграция применяется к базе с прежней схемой. При этом существующие записи разрешённых форматов сохраняются.
- **AC-09:** Актуализированы документация и примеры API, специфические видеотесты исключены.
- **AC-10:** Не изменены сценарии создания, чтения, редактирования, фильтрации багов и обновления статусов.

## 5. За рамками

Авторизация, новые типы файлов, новые лимиты, переработка UX, переход на иное хранилище, изменения контрактов остальных API и расширение CI — вне задачи.

## 6. Согласование

Это **черновик SDD**, не команда на автоматическую реализацию. Заказчик должен утвердить документ до передачи Codex. После утверждения зафиксировать итоговую базовую ветку и сверить миграции в актуальном коммите.
