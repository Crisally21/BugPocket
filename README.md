# BugPocket

Учебное веб-приложение для учёта багов. Java 17, Spring Boot 4.1.1, Maven Wrapper, PostgreSQL и Liquibase.

## Запуск

Установи JDK 17. PostgreSQL можно запустить через compose.yaml — инструкция ниже в разделе «PostgreSQL в Docker». В текущем окружении JAVA_HOME указывает на отсутствующий GraalVM. Перед командами Maven в PowerShell выполни:

```powershell
$env:JAVA_HOME = 'C:\Program Files\Java\jdk-17'
```

При запуске через Docker база и пользователь создаются автоматически. Для собственной установки PostgreSQL создай пустую базу bugpocket и пользователя с правами на создание таблиц в ней.
В PowerShell задай DB_URL, DB_USERNAME и DB_PASSWORD для своей базы, затем выполни:

```powershell
.\mvnw.cmd spring-boot:run
```

По умолчанию URL базы — jdbc:postgresql://localhost:5432/bugpocket, пользователь — bugpocket.
Пароль задаётся через DB_PASSWORD; реальные пароли не записывай в файлы проекта.
Liquibase создаёт таблицу, Hibernate проверяет её соответствие модели.

Сервер слушает только 127.0.0.1:8080. В этой локальной учебной версии нет авторизации.
В браузере открой http://localhost:8080/ — увидишь интерфейс BugPocket. JSON-список доступен по /api/bugs.
Фронтенд отдаёт тот же сервер Spring Boot; отдельная сборка не нужна.

## PostgreSQL в Docker

Установи и запусти Docker Desktop с Linux-контейнерами. Из корня проекта в PowerShell:

```powershell
$env:DB_USERNAME = 'bugpocket'
$env:DB_PASSWORD = Read-Host 'Задай пароль для локальной БД'
$env:DB_URL = 'jdbc:postgresql://localhost:5432/bugpocket'
docker compose up -d --wait
docker compose ps
```

Compose использует [официальный образ PostgreSQL 17](https://hub.docker.com/_/postgres), создаёт базу bugpocket
и пользователя из DB_USERNAME. Порт 5432 доступен только на этом компьютере.
DB_PASSWORD обязателен; пароль не хранится в compose.yaml. Один и тот же пароль получает PostgreSQL и Spring Boot.

После готовности базы запусти приложение в этом же терминале:

```powershell
$env:JAVA_HOME = 'C:\Program Files\Java\jdk-17'
.\mvnw.cmd spring-boot:run
```

Открой http://localhost:8080/. Таблицы создаст Liquibase при запуске приложения.
Если запускаешь приложение из IDE, укажи там те же DB_URL, DB_USERNAME и DB_PASSWORD.
Переменные PowerShell действуют только в текущем терминале и запущенных из него процессах.
В новом терминале задавай тот же пароль: переменные инициализации образа применяются только к пустому тому;
изменение DB_PASSWORD в окружении не меняет пароль уже созданного пользователя.

Полезные команды:

```powershell
docker compose logs -f postgres
docker compose stop
docker compose start --wait
docker compose down
```

Данные хранятся в именованном томе postgres_data и сохраняются после stop и down.
Команда down с флагом -v удаляет том вместе со всеми данными — для обычной остановки этот флаг не нужен.
Если порт 5432 уже занят другой БД, сначала останови её или измени порт в compose.yaml и DB_URL согласованно.

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | /api/bugs | Список, необязательные фильтры status и priority |
| GET | /api/bugs/{id} | Один баг |
| POST | /api/bugs | Создать |
| PUT | /api/bugs/{id} | Заменить редактируемые поля, сохранив статус |
| PATCH | /api/bugs/{id}/status | Изменить статус |

Тело создания и редактирования:

```json
{"header":"Не открывается страница","steps":"Открыть ссылку","actualResult":"Ошибка 500","expectedResult":"Страница открыта","environment":"Firefox","priority":"HIGH"}
```

header и priority обязательны. header: до 200 символов; steps, actualResult, expectedResult: до 10000; environment: до 2000.
Необязательные поля при PUT можно очистить через null или отсутствие поля.

relatedTaskUrl — одна необязательная ссылка на связанную задачу. HTTP/HTTPS сохраняются;
для адреса без схемы, например tracker.company.local/TASK-123, сервер добавляет https://.
Некорректная ссылка возвращает 400 с errors.relatedTaskUrl. Сервер проверяет синтаксис
локально, без HTTP/DNS-запросов к задаче. Дополнительный лимит длины URL не задан.

Поле можно передать в POST/PUT вместе с остальными полями; GET списка и карточки возвращает
сохранённый URL. При PUT отсутствие relatedTaskUrl, null, пустая строка или пробелы очищают ссылку.
Изменение URL обновляет updatedAt через существующую логику Bug; status при PUT сохраняется.
На этапе T-01 поле доступно через API; форма интерфейса будет добавлена отдельно в T-02.

Приоритеты: LOW, MEDIUM, HIGH. Статусы: NEW, IN_PROGRESS, FIXED.
Новый баг получает NEW. Смена статуса: {"status":"IN_PROGRESS"}. Разрешён любой из трёх статусов, включая повторное открытие.
Даты и номер назначает сервер. Список отсортирован от новых к старым.
Неверные данные возвращают 400, отсутствующий баг — 404, ошибки полей находятся в errors.

Пример создания в PowerShell:

```powershell
$bugBody = @{ header = 'Login error'; priority = 'HIGH' } | ConvertTo-Json
Invoke-RestMethod http://localhost:8080/api/bugs -Method Post -ContentType 'application/json' -Body $bugBody
```

После создания обнови список в браузере, перезапусти сервер и убедись, что запись осталась.

## Структура

- model: Bug, BugStatus, BugPriority — данные и отображение на таблицу.
- dto: BugRequest, BugStatusRequest, BugResponse — вход и выход API.
- controller: BugController — HTTP-запросы.
- service: BugService — операции с багами и транзакции.
- repository: BugRepository — запросы в базу.
- exception: BugNotFoundException, ApiExceptionHandler — понятные HTTP-ошибки.
- db/changelog: миграция таблицы bug.

Сохранены исходные поля пользовательского Bug: header, steps, actualResult, expectedResult, environment.
Для MVP убраны Kafka, Elasticsearch, Spring Cloud Config/Eureka/Gateway, Security, Prometheus и их тестовые зависимости:
сейчас нет задач, требующих этих сервисов. Добавлен Validation для проверки запросов.
Actuator оставлен для проверки состояния. H2 используется только тестами.

## Тесты

```powershell
.\mvnw.cmd test
```

Тесты запускают приложение с H2 в памяти, применяют ту же миграцию и проверяют API через MockMvc:
создание, чтение, редактирование, статусы, фильтры, неверные запросы и 404.
Это не заменяет отдельную проверку на PostgreSQL.



## Интерфейс

Открой http://localhost:8080/ после запуска Spring Boot. Отдельный сервер фронтенда, Node.js и npm для обычного запуска не нужны.

- Список: поиск по названию и номеру, фильтры по статусу и приоритету.
- Карточка: шаги, результаты, окружение, даты и смена статуса.
- Создание и редактирование: проверка полей, ошибки сервера возле полей, сохранение введённого текста при сбое.
- Навигация предупреждает о несохранённых изменениях; кнопки защищены от повторной отправки.
- Есть состояния загрузки, пустого списка и ошибки с повторной попыткой.
- На небольших экранах таблица отображается карточками.

Статические файлы лежат в src/main/resources/static:
index.html — каркас, styles.css — оформление, app.js — экраны и API,
ui.js — маршруты, фильтры и проверка данных, favicon.svg — значок.
Используются HTML, CSS и JavaScript без сборщика. Адреса вида /#/bugs/1 работают после обновления страницы.
Статус и приоритет фильтруются сервером; поиск по названию и номеру выполняется в браузере среди полученных записей.
Фильтры и поиск сохраняются в адресе страницы.

### Быстрый просмотр без PostgreSQL

Для временного просмотра можно подключить уже имеющуюся тестовую H2. В том же терминале с настроенным JAVA_HOME:

```powershell
.\mvnw.cmd -B -ntp spring-boot:run '-Dspring-boot.run.useTestClasspath=true' '-Dspring-boot.run.arguments=--server.port=8081 --server.address=127.0.0.1 --spring.datasource.url=jdbc:h2:mem:ui-preview --spring.datasource.username=sa --spring.datasource.password='
```

Открой http://127.0.0.1:8081/. Это база в памяти: записи исчезнут после остановки.
Для обычной работы с сохранением данных используй запуск с PostgreSQL выше.

### Проверка в браузере

1. Нажми «Добавить баг», заполни название, шаги и приоритет, затем «Создать баг».
2. В карточке нажми «Редактировать», измени ожидаемый результат и сохрани.
3. Выбери статус «Исправлен» и нажми «Сохранить статус».
4. Перейди в «Исправленные», найди запись по названию или номеру, проверь фильтр приоритета.
5. В новой форме попробуй сохранить пустое название: ошибка появится возле поля.
6. Введи текст и нажми «Отмена»: интерфейс предложит подтвердить уход.
7. Уменьши ширину окна: список должен отображаться карточками без горизонтальной прокрутки страницы.

### Проверки JavaScript

Только для разработки и тестов нужен Node.js (проверено на 24.18.0).
Зависимость jsdom в package.json нужна для тестов DOM и не включается в приложение.

```powershell
npm.cmd ci
npm.cmd run check:ui
npm.cmd run test:ui
```

Обычный запуск выполняет 14 тестов и пропускает один тест с настоящим сервером.
Для полного прогона запусти временный сервер на порту 8081 командой выше, затем в другом терминале:

```powershell
$env:BUGPOCKET_TEST_URL = 'http://127.0.0.1:8081/'
npm.cmd run test:ui
Remove-Item Env:BUGPOCKET_TEST_URL
```

Полный прогон выполняет 15 тестов, в том числе создание, редактирование, смену статуса и фильтрацию через настоящий REST API.
Этот тест создаёт запись в указанной базе: используй временный сервер.
jsdom проверяет поведение DOM, но не рисует страницу и не заменяет визуальную проверку в браузере.

Следующий шаг — проверить интерфейс с постоянной PostgreSQL-базой и при необходимости уточнить оформление.
